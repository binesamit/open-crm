## 2. דרישות

- **כדי לנסות או לצוות קטן:** כל מחשב עם **Docker** (Docker Desktop ב-Windows / macOS), **1GB זיכרון** ומעט דיסק.
  זה הכול: אין מסד נתונים להתקין ואין קובץ הגדרות.
- **לצוות גדול או לייצור:** שרת Linux עם **Docker Engine 24+** ו-**Compose plugin 2.24+**, **2 ליבות ו-4GB זיכרון**
  לבנייה הראשונה, **כ-5GB דיסק** ועוד המידע שלכם, **שם דומיין** ו-reverse proxy עם TLS (HTTPS). רשות: שרת SMTP
  למייל; אחסון S3 חיצוני לקבצים.

פירוט: [SELF-HOSTING.md ← Requirements](SELF-HOSTING.md#requirements).

## 3. התקנה בדקה

מריצים את ה-image המפורסם (כל גרסה מפרסמת אחד):

```sh
docker run -it --rm -p 3000:3000 -v bines_data:/data ghcr.io/binesamit/open-crm:latest
```

או לבנות בעצמכם מהריפו (כ-5 דקות): `docker build -f docker/Dockerfile -t bines-os .`, ואז להריץ `bines-os` במקום שם ה-image.

פותחים את **http://localhost:3000** ויוצרים את חשבון הבעלים בדפדפן. זהו: מסד הנתונים, הקבצים שמעלים והמפתחות
הסודיים נוצרים בהפעלה הראשונה ונשמרים ב-volume בשם `bines_data` (עוצרים עם Ctrl+C; אותה פקודה שוב ממשיכה מאיפה
שעצרתם). כדי שירוץ ברקע: `-d --restart unless-stopped` במקום `-it --rm`.

- **כתובת אחרת** (דומיין, פורט אחר): מוסיפים `-e WEB_ORIGIN=https://work.example.com`.
- **מייל**: כבוי עד שמוסיפים SMTP (`-e SMTP_HOST=… -e SMTP_PORT=587 -e SMTP_USER=… -e SMTP_PASS=… -e
  EMAIL_FROM=…`). בלעדיו נכנסים עם סיסמה, והזמנות נותנות קישור להעתקה.
- **גבו את ה-volume** (`/data`): הכול שם, כולל `secrets.json`. בלעדיו אי אפשר לקרוא בחזרה סודות שמורים.
- **מגבלות:** תהליך אחד עם מסד נתונים מוטמע — מתאים לניסיון ולצוותים קטנים. ליותר אנשים או לכמה שרתים עוברים
  ל-PostgreSQL: ההתקנה לייצור שלמטה, או אותו image עם `-e DATABASE_URL=postgres://…` (ו-S3 עם משתני `S3_*`).

### התקנה על שרת בפקודה אחת

בשרת לינוקס (כל VPS) עם דומיין שה-DNS שלו מפנה אליו:

```sh
git clone https://github.com/binesamit/open-crm.git bines-os && sudo bash bines-os/scripts/install.sh
```

הסקריפט שואל על הדומיין ועל המייל של הבעלים, מתקין Docker אם חסר, ומריץ את אותו image מאחורי Caddy עם HTTPS
אוטומטי (Let's Encrypt) וגיבוי יומי של `/data` לתיקייה `/opt/bines-os/backups`. הרצה נוספת משדרגת, והנתונים
והתשובות נשמרים. דגלים, שחזור ופרטים: `docs/SELF-HOSTING.md`, בפרק "Install on a server in one command".

### התקנה לייצור (PostgreSQL + אחסון קבצים)

```sh
git clone https://github.com/binesamit/open-crm.git bines-os && cd bines-os
cp .env.example .env
```

פותחים את `.env` וממלאים את החלק **SELF-HOSTING** בסוף. הערכים החובה ריקים בכוונה:

```sh
APP_URL=https://<your-domain>                # or http://localhost:3000 to try it locally
ADMIN_EMAIL=you@<your-domain>                # the first administrator
AUTH_SECRET=...                              # openssl rand -base64 48
SECRET_MASTER_KEY=...                        # openssl rand -base64 32
POSTGRES_PASSWORD=...                        # openssl rand -hex 24
STORAGE_SECRET_KEY=...                       # openssl rand -hex 24
```

מדביקים את **הפלט** של כל פקודת `openssl`, לא את הפקודה. ואז:

```sh
docker compose -f docker-compose.prod.yml up -d
docker compose -f docker-compose.prod.yml ps   # wait until "api" is healthy
```

ההפעלה הראשונה בונה את ה-image (כמה דקות). אחר כך פותחים את `APP_URL`.

**שמרו עותק של `.env` במקום בטוח, מחוץ לשרת.** בלי `SECRET_MASTER_KEY` אי אפשר לקרוא בחזרה סודות שמורים.

## 4. המנהל הראשון

**התקנה בדקה:** בכניסה הראשונה מופיע המסך **יצירת חשבון הבעלים** (שם, מייל, סיסמה ושם המערכת — רשות). מי שנרשם
הופך ל**בעל הפלטפורמה** — הוא רואה את **קונסולת הבעלים** (`/owner`), ושם נמצא הרישוי — ולמנהל של החשבון הראשון.
המסך עובד פעם אחת: ברגע שהחשבון קיים הוא נעלם, והכתובת היא מסך הכניסה.

**התקנה לייצור:** במסד נתונים ריק, ההפעלה הראשונה יוצרת את החשבון הראשון ומזמינה את `ADMIN_EMAIL` כמנהל שלו,
והוא גם בעל הפלטפורמה.

- **מייל מוגדר**: פותחים את האפליקציה, מקלידים את `ADMIN_EMAIL`, נכנסים מהקישור שמגיע במייל ומאשרים את ההזמנה.
  (גם המסך **יצירת חשבון הבעלים** בדפדפן עובד — רק עם `ADMIN_EMAIL`.)
- **עוד אין מייל**: יוצרים קישור חד-פעמי (בתוקף 7 ימים) ופותחים אותו כדי לקבוע סיסמה:

  ```sh
  docker compose -f docker-compose.prod.yml exec api node dist/first-admin-link.js
  ```

ההרשמה בהזמנה בלבד (אלא אם מפעילים הרשמה עצמית, למטה). את כל השאר מזמינים מ"ניהול".

### הרשמה עצמית (כבויה כברירת מחדל)

אנשים יכולים גם להירשם לבד — אותה תכונה כמו בענן מתארח, **כבויה** עד שבעל הפלטפורמה מדליק אותה (קונסולת הבעלים ←
תוכניות ← **הרשמה עצמית**). כל עוד היא כבויה, `/signup` מציג שההרשמה סגורה, ובמסך הכניסה אין קישור הרשמה. שני מצבים:

- **הצטרפות לפי דומיין** — מי שהמייל שלו מדומיין מאושר מצטרף ל**חשבון קיים** כחבר. דורש **מייל יוצא** (SMTP או
  Resend). לאיזה חשבון ומאילו דומיינים — זו החלטה של החשבון: המנהלים
  שלו מוסיפים את הדומיינים (ניהול ← אבטחה ← דומיינים), מאמתים כל אחד (מיד, אם כתובת המייל המאומתת שלהם בדומיין; אחרת
  ברשומת DNS מסוג TXT‏ `bines-domain-verification=<token>` שמוצגת שם) ומדליקים **הצטרפות אוטומטית** עם תפקיד (חבר
  או צופה). דומיינים של תיבות דואר חינמיות לא מתאימים, ודומיין מאומת שייך לחשבון אחד בלבד. גם במצב הרשמה פתוחה, מי
  שהמייל שלו מדומיין מאומת מצטרף לחשבון הזה במקום לפתוח חשבון חדש.
- **הרשמה פתוחה** — כל אחד פותח **חשבון חדש** משלו (אירוח לאחרים). דורש מייל יוצא, תוכנית ברירת מחדל ציבורית,
  וכשמבקשים — מפתחות Turnstile. בלי שום מפתח.

הכרטיס מציג מה עוד חסר (מייל, מפתחות קפצ'ה, תוכנית ברירת מחדל ציבורית, דרך הרשמה, מסמך משפטי מפורסם שדורש הסכמה); כל
פריט חסר מקשר למקום שבו מגדירים אותו. אם משהו מוסר אחר כך (המייל, התוכנית), ההרשמה עונה מיד "לא זמינה כרגע" והמתג
נשאר כמו שהיה.

### כרטיס "צעדים ראשונים"

עד שההתקנה מוגדרת, קונסולת הבעלים נפתחת בכרטיס **צעדים ראשונים**: מייל יוצא, מסמכים משפטיים מפורסמים, תוכנית
ציבורית ראשונה, והרשמה עצמית דלוקה ומוכנה. כל צעד מסומן לבד ברגע שההגדרה קיימת, ומקשר למקום שבו עושים אותו.
הכרטיס נעלם כשכל הצעדים הושלמו, או כשלוחצים **הסתרה** (והוא נשאר מוסתר).

## 5. שאלון הרישום (רשות)

הרישום הוא **רשות** ולא משנה שום דבר במה שהתוכנה עושה: התקנה שלא נרשמה מעולם מחזיקה את כל היכולות, לכל מספר של
אנשים ופריטים. הרישום נותן להתקנה מפתח **"קהילה רשומה"** חינם מספק — רשומה שההתקנה הזו מוכרת לו, שימושית כשקונים
ממנו תמיכה או אירוח.

**איפה זה.** קונסולת הבעלים ← **רישוי** ← כרטיס רישיון ← **הרשמה**, ורק כשמוגדר להתקנה שרת רישיונות (ספק):
קונסולת הבעלים ← רישוי ← הגדרות רישוי ← כתובת שרת הרישיונות, או, כברירת מחדל, `LICENSE_SERVER_URL` ב-`.env`.
**אין כתובת קבועה בקוד**: בלי אחד מהם שום שרת לא נוצר איתו קשר. עדיין אפשר להדביק מפתח שקיבלתם.

**השאלות:** שם החברה, גודל (1–5 / 6–20 / 21–100 / 100+), תפקיד, למה תשתמשו (CRM / משימות ופרויקטים / שירות
לקוחות / אחר), אימייל (התשובה החובה היחידה), ו"אפשר לשלוח לי עדכונים במייל" — **אף פעם לא מסומן מראש**.

**מה נשלח, ורק כשלוחצים "שליחה":** התשובות שלכם, מספר ההתקנה (מספר אקראי שנוצר בהפעלה הראשונה; הוא לא מזהה שום
דבר אחר — לא שם שרת ולא כתובת), הגרסה ושפת הממשק (`he` / `en`). ותו לא.

**מה קורה אחר כך:**

1. שרת הרישיונות שולח קישור אימות במייל (בתוקף 48 שעות).
2. פותחים אותו. בעמוד מופיע מפתח "קהילה רשומה".
3. אם השרת שלכם מגיע לשרת הרישיונות, המפתח **מותקן לבד**: המסך בודק כל כמה שניות (או לחצו "בדיקה עכשיו"). אפשר גם
   לסגור ולחזור אחר כך: קונסולת הבעלים ← רישוי. מפתח שכבר בתוקף לא מוחלף לעולם.

**שרת בלי אינטרנט.** בטופס, תחת "בלי אינטרנט בשרת?", לוחצים **הרשמה מדפדפן אחר**. נפתח
`<license server>/register?instance=<מספר ההתקנה שלכם>` — אפשר לפתוח אותו בכל מחשב. נרשמים שם, מאשרים את המייל,
מעתיקים את המפתח מעמוד האימות ומדביקים בכרטיס הרישיון (ראו [הפעלת מפתח](#7-הפעלת-מפתח-רישיון)).

## 6. מהדורות

יש מהדורה אחת. **הכול נמצא בכל התקנה, בלי מפתח**: לוחות, אוטומציות (גם המתקדמות), AI עם מפתח ספק משלכם, מסמכים,
דשבורדים, טפסים, אורחים ופורטל לקוחות, API / MCP / webhooks / OAuth, תוספים, כניסה עם Google / Microsoft ואימות
דו-שלבי, יומן ביקורת, מרכז השגיאות, עמודות סוד, קונסולת הבעלים עם כמה חשבונות, אירוח חשבונות לאחרים ומכירת חבילות,
ומיתוג עצמי (white-label) — לכל מספר של אנשים ופריטים.

מפתח רישיון הוא **רשומה מספק**, לא מנעול: הוא נוקב בחבילה (קהילה רשומה / עסקי / ארגוני — השמות שהספק נותן להצעות
התמיכה שלו), במספר מושבים, ברמת תמיכה ובתוקף. קונסולת הבעלים מציגה מה כתוב במפתח; מעל מספר המושבים מופיעה אזהרה
בלבד; כשהוא פג — רק הרשומה פגה. שום דבר שאתם משתמשים בו לא נכבה.

**אירוח לאחרים.** כדי לארח חשבונות לאנשים אחרים ולגבות מהם תשלום לא צריך מפתח: קונסולת הבעלים ← חבילות (מגבלות
ומחירים לכל חבילה), מסמכים משפטיים, ואז מתג **הרשמה עצמית** — כרטיס "צעדים ראשונים" מראה מה עוד חסר.

## 7. הפעלת מפתח רישיון

מפתח נראה כך: `lic1.<…>.<…>`. הוא נבדק **על השרת שלכם, בלי חיבור לאינטרנט**.

**בקונסולת הבעלים** (`/owner?section=licensing`):

1. קונסולת הבעלים ← **רישוי** ← כרטיס **רישיון**.
2. מדביקים את המפתח בשדה **מפתח רישיון** ולוחצים **התקנת הרישיון** — או לוחצים **העלאת קובץ רישיון** (קובץ
   `.lic`, `.key` או `.txt` שבו המפתח).
3. הכרטיס מציג מיד את פרטי המפתח.

**דרך ה-API** (בעל הפלטפורמה): `PUT /api/v1/platform/license` עם `{ "key": "lic1.…" }`; `GET` קורא את הכרטיס,
`DELETE` מסיר את המפתח.

**אין משתנה סביבה למפתח** (אין `BINES_LICENSE_KEY`): המפתח נשמר במסד הנתונים, ולכן הוא שורד הפעלה מחדש, שדרוג
וגיבוי-ושחזור.

מפתח מותקן רק אם הוא בתוקף **כאן**. אחרת הקונסולה אומרת למה:

| הודעה                            | פירוש                                                                     |
| -------------------------------- | ------------------------------------------------------------------------- |
| המפתח לא במבנה הנכון             | חסר בו חלק — העתיקו שוב, במלואו.                                          |
| המפתח לא חתום על ידי בעל הרישיון | הוא לא הונפק על ידי בעל הרישיון של הגרסה הזו (או ששונה).                  |
| תוכן המפתח לא תקין               | הוא פגום. בקשו אותו שוב.                                                  |
| פג התוקף של הרישיון              | עבר את התפוגה ואת תקופת החסד. בקשו מפתח מחודש.                            |
| המפתח הונפק להתקנה אחרת          | הוא נקשר למספר התקנה אחר. ראו [שאלות נפוצות: מעבר שרת](#14-שאלות-נפוצות). |

**הסרת הרישיון** מסירה את הרשומה מהכרטיס. שום דבר אחר לא משתנה ושום מידע לא נמחק.

## 8. כרטיס הרישיון

קונסולת הבעלים ← רישוי ← רישיון מציג:

- **מצב** (בטבלה למטה), **הונפק ל**, **מהדורה**, **יכולות**, **בתוקף עד**;
- **משתמשים**: "N פעילים מתוך M" (או "ללא הגבלה"). משתמש פעיל = אדם (לא זהות שירות) עם חברות פעילה, לא כאורח,
  בחשבון כלשהו. מעל המכסה מופיעה **רק התראה; שום דבר לא נחסם**;
- **תקופת חסד**, **תמיכה**, **הותקן**, **בדיקה מקוונת אחרונה**;
- **מספר ההתקנה** — המספר האקראי שמפתח יכול להיקשר אליו. מוסרים אותו לבעל הרישיון כשמבקשים מפתח.

| מצב          | פירוש                                                    | מה עובד |
| ------------ | -------------------------------------------------------- | ------- |
| אין רישיון   | לא הותקן מפתח                                            | הכול |
| בתוקף        | בתוקף                                                    | הכול |
| מסתיים בקרוב | בתוקף, נגמר בתוך 30 יום — באנר                           | הכול |
| בתקופת חסד   | עבר את התפוגה, בתוך ימי החסד (ברירת מחדל 14) — באנר אדום | הכול |
| פג תוקף      | עבר את תקופת החסד                                        | הכול |
| בוטל         | בדיקה מקוונת גילתה שבעל הרישיון ביטל אותו                | הכול |
| לא תקין      | לא קריא, לא חתום על ידי בעל הרישיון, או של התקנה אחרת    | הכול |

**בדיקה מקוונת** (בכרטיס) שואלת את שרת הרישיונות אם המפתח עדיין פעיל ואם יש לו מפתח חדש יותר (חידוש או שינוי
מהדורה); מפתח חדש מותקן לבד. נשלחים רק מספר ההתקנה ומספר המפתח. בלי בדיקה מקוונת, ביטול לא ידוע — ומפתח
פשוט רץ עד התפוגה שלו.

## 9. חידוש ותפוגה

- מפתחות עסקי וארגוני תקפים בדרך כלל **לשנה** (הספק קובע). מפתח "קהילה רשומה" לא פג.
- **30 יום לפני** הסוף: באנר "מסתיים בקרוב".
- **בתפוגה**: **תקופת חסד** (14 יום, אלא אם המפתח קובע אחרת). הכול ממשיך לעבוד; באנר אדום אומר עד מתי.
- **אחרי תקופת החסד**: הכרטיס מציג "פג תוקף" — רשומת ההפעלה והתמיכה הסתיימה. **שום דבר לא נכבה**, שום דבר לא
  הופך לקריאה בלבד, **שום מידע לא נמחק**, וכל המשתמשים ממשיכים לעבוד.
- **חידוש**: בעל הרישיון מחדש את הרישיון (אותו רישיון, תאריך חדש). את המפתח החדש מקבלים ב**בדיקה מקוונת**, או
  מדביקים את המפתח שהגיע במייל.

## 10. שדרוג לגרסה חדשה

1. מגבים את מסד הנתונים (ואת הקבצים) — ראו [Backups](SELF-HOSTING.md#backups).
2. מושכים ובונים מחדש:

   ```sh
   git pull
   docker compose -f docker-compose.prod.yml up -d --build
   ```

3. השירות `migrate` מריץ את שינויי מסד הנתונים לפני שהאפליקציה עולה.

שינויי מסד הנתונים רק מתקדמים: כדי לחזור אחורה משחזרים את הגיבוי שנלקח לפני השדרוג. מפתח הרישיון ומספר ההתקנה
שמורים במסד הנתונים, ולכן לא משתנים. פירוט: [SELF-HOSTING.md ← Upgrades](SELF-HOSTING.md#upgrades).

## 11. פרטיות וטלמטריה

שום דבר לא יוצא מהשרת שלכם בלי פעולה של בעל הפלטפורמה. בדיוק מה יכול להישלח, ומתי:

| מתי                             | מה נשלח לשרת הרישיונות                                             | איך מונעים                                     |
| ------------------------------- | ------------------------------------------------------------------ | ---------------------------------------------- |
| **שליחה** בשאלון הרישום         | התשובות, מספר ההתקנה, הגרסה, שפת הממשק                             | מדלגים, או לא מגדירים שרת רישיונות             |
| **בדיקה מקוונת** בכרטיס הרישיון | מספר ההתקנה ומספר המפתח                                            | לא לוחצים; `BINES_UPDATE_CHECK=false`          |
| **טלמטריה**, רק אם הפעלתם       | פעם ביום: `{ "instance_id", "version", "active_users", "boards" }` | **כבויה כברירת מחדל**; `BINES_TELEMETRY=false` |

- **לא נשלחים לעולם:** תוכן לוחות, שמות פריטים, קבצים, רשימת המשתמשים, כתובות פנימיות.
- **הטלמטריה כבויה כברירת מחדל.** להפעלה: קונסולת הבעלים ← רישוי ← הגדרות רישוי ← **שליחת נתוני שימוש (פעם
  ביום)**. הכרטיס מראה **בדיוק** מה יישלח לפני שמפעילים, ומתי נשלח לאחרונה.
- **כיבוי מוחלט** ב-`.env`, בלי קשר למה שבקונסולה:

  ```sh
  BINES_TELEMETRY=false      # no usage data, ever
  BINES_UPDATE_CHECK=false   # no online key check (and no update check)
  ```

  ואז מחילים: `docker compose -f docker-compose.prod.yml up -d`. כשלא מוגדר שרת רישיונות בכלל (`LICENSE_SERVER_URL`
  ריק ואין כלום בהגדרות הרישוי), הפלטפורמה לא פונה לשום שרת רישיונות.

- הטלמטריה של ספריית הכניסה עצמה כבויה בקוד.

## 14. שאלות נפוצות

**חייבים להירשם?** לא. שום דבר בתוכנה לא דורש מפתח או רישום; בכל התקנה יש את כל היכולות, לכל מספר של אנשים
ופריטים. הרישום (חינם) רק רושם את ההתקנה שלכם אצל ספק.

**הפלטפורמה עובדת בלי אינטרנט?** כן. מפתחות נבדקים בלי רשת. רק הרישום, "בדיקה מקוונת" והטלמטריה (כבויה כברירת
מחדל) משתמשים ברשת.

**מה קורה אם שכחתי לחדש?** מקבלים התראה 30 יום לפני, ואחר כך 14 ימי חסד. אחרי זה הכרטיס אומר "פג תוקף" — וזה
הכול: שום דבר לא נכבה, שום מידע לא נמחק ואף אחד לא ננעל בחוץ. התמיכה של הספק עשויה להסתיים, לפי ההסכם איתו.

**עברתי לשרת חדש. המפתח עדיין עובד?** אם שחזרתם גיבוי של מסד הנתונים — כן: מספר ההתקנה עבר איתו. אם התחלתם
התקנה חדשה — יש לה מספר התקנה חדש: שלחו את המספר החדש (קונסולת הבעלים ← רישוי) לבעל הרישיון ובקשו מפתח חדש.
מפתחות שהונפקו בלי מספר התקנה עובדים בכל מקום.

**אני צריך יותר משתמשים ממה שהמפתח מכסה.** שום דבר לא נחסם, מופיעה רק התראה. בקשו מבעל הרישיון מפתח עם יותר
משתמשים.

**אפשר לראות בדיוק מה הטלמטריה שולחת?** כן: קונסולת הבעלים ← רישוי ← הגדרות רישוי מציג את התוכן המדויק. היא
כבויה אלא אם הפעלתם.

**יכולת שאני משתמש בה היום יכולה להפוך לבתשלום?** לא. יכולת שחינמית היום נשארת חינמית.

**אפשר להסיר את המיתוג של הפלטפורמה?** כן. אפשר לקבוע שם מוצר, לוגו וצבעים משלכם, גם כשמארחים את הפלטפורמה
לאחרים. שומרים על הייחוס שהרישיון מבקש (`LICENSE-EXCEPTIONS.md`), ולא משתמשים בשם או בלוגו של הפרויקט לגרסה ששונתה
([`TRADEMARKS.md`](../TRADEMARKS.md)).

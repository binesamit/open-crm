# MCP, ‏API וחיבורים לכלים אחרים

גרסה באנגלית: [mcp-and-api.md](mcp-and-api.md)

## למה זה טוב

מחברים את Bines OS לכלים שאתם כבר עובדים איתם:

- אפליקציות AI כמו Claude, ‏ChatGPT, ‏Cursor או VS Code קוראות ומשנות את הבורדים דרך MCP, בשמכם.
- Make, ‏n8n וסקריפטים שלכם יוצרים ומעדכנים פריטים עם טוקן API.
- Webhooks שולחים אירועים מהבורד לכתובת חיצונית ברגע שהם קורים.

כל חיבור פועל בשם אדם (או בשם שירות מוגדר) ובהרשאות שלו, לא יותר. המדריך הזה למשתמשים. מפתחים ימצאו את כל הנקודות ב[תיעוד ה-API](../06-API.md).

ייתכן ש-API, ‏MCP וחיבור אפליקציות AI לא כלולים בכל חבילה. אם הם לא כלולים, תופיע ההודעה "לא כלול בחבילה שלכם — שדרגו כדי להשתמש".

## לפני שמתחילים: מה המנהל קובע

ב"ניהול החשבון" ← "AI ו-MCP", הכרטיס "שרת MCP" קובע את החיבור של אפליקציות AI:

- "MCP פעיל בחשבון" – כשהוא כבוי, אף כלי AI לא יכול להתחבר.
- "מי יכול לחבר כלי AI" – "רק מנהלים", "חברי צוות" או "חברי צוות וצופים". מנהלים תמיד יכולים, אורחים אף פעם.
- "פעולות רגישות (מחיקה)" – "מותר" או "חסום". מחיקה מעבירה לסל ואפשר לבטל אותה. כשחסום, הכלים האלה לא מוצעים לאפליקציות AI.

באותו כרטיס מופיעות "כתובת ה-MCP" (אותה כתובת לכל כלי) ו"הכלים שתקבלו" – רשימת הפעולות שאפליקציות AI יכולות לבצע.

## חיבור Claude.ai או ChatGPT

‏Claude.ai ו-ChatGPT מתחברים דרך מסך כניסה ואישור (OAuth). מדביקים רק את כתובת ה-MCP, בלי טוקן.

חיבור Claude.ai:

1. כתובת ה-MCP היא הכתובת של Bines OS שלכם ואחריה ‎/mcp (למשל ‎https://work.example.com/mcp). מנהלים יכולים להעתיק אותה מ"ניהול החשבון" ← "AI ו-MCP".
2. ב-Claude פותחים Settings ← Connectors ← Add custom connector.
3. השם: "Bines OS", והכתובת: כתובת ה-MCP.
4. לוחצים Connect, נכנסים ל-Bines OS ומאשרים (ראו "מסך האישור" בהמשך).

חיבור ChatGPT:

1. ב-ChatGPT פותחים Settings ← Apps & Connectors ← Advanced ומפעילים Developer mode.
2. לוחצים Create. שם: "Bines OS", כתובת: כתובת ה-MCP, אימות: OAuth.
3. לוחצים Connect, נכנסים ל-Bines OS ומאשרים.

### מסך האישור

כשאפליקציית AI מבקשת להתחבר, Bines OS מציג את המסך "חיבור אפליקציית AI":

1. בודקים את שם האפליקציה. אם מופיע "לא מאומת", מאשרים רק אם אתם אלה שהתחלתם את החיבור.
2. "לאיזה חשבון לחבר?" – חיבור אחד = חשבון אחד. לחשבון נוסף מתחברים שוב.
3. "מה מותר לה" – "קריאה", "עריכה" ו"אוטומציות". צופה יכול לחבר לקריאה בלבד.
4. "באילו בורדים" – "כל הבורדים שלי" (כולל בורדים שיתווספו בהמשך) או "רק בורדים שאבחר".
5. לוחצים "אישור וחיבור" או "ביטול".

אם החשבון מחייב אימות דו-שלבי או כניסה דרך Google או Microsoft, עושים את זה קודם ואז מתחברים.

## חיבור Claude Code, ‏Cursor או VS Code

הכלים האלה עובדים עם טוקן API אישי.

1. יוצרים טוקן אישי (ראו "יצירת טוקן API" בהמשך). ההרשאות של הטוקן הן מה שהכלי יקבל, למשל קריאה בלבד או רק בורדים מסוימים.
2. מוסיפים לכלי את כתובת ה-MCP עם הטוקן. מנהלים ימצאו שורות מוכנות להעתקה ב"ניהול החשבון" ← "AI ו-MCP" ← "איך מתחברים":
   - Claude Code – פקודה להרצה בטרמינל, עם הטוקן במקום <TOKEN>.
   - Cursor – מוסיפים את הבלוק לקובץ ‎~/.cursor/mcp.json (או ‎.cursor/mcp.json בפרויקט).
   - VS Code – מוסיפים את הבלוק לקובץ ‎.vscode/mcp.json.

## צפייה באפליקציות מחוברות וניתוק

- החיבורים שלכם: "הפרופיל שלי" ← "טוקני API". לכל חיבור רואים מתי חובר, מתי היה בשימוש לאחרונה ולאילו בורדים יש לו גישה.
- מנהלים רואים את החיבורים של כולם בכרטיס "אפליקציות AI מחוברות" ב"ניהול החשבון" ← "AI ו-MCP".
- לוחצים "ניתוק". האפליקציה מאבדת את הגישה מיד, ואפשר לחבר אותה שוב בכל זמן.

## מה אפליקציות AI יכולות לעשות, ואיך מבטלים

- אפליקציית AI פועלת בדיוק בהרשאות של מי שחיבר אותה ובמה שהוא אישר.
- כל שינוי שלה נרשם ביומן הפעילות בשם אותו אדם, עם סימון שהגיע דרך MCP.
- כל קריאה אפשר לבטל כצעד אחד (לאפליקציה יש כלי ביטול, והשינוי מופיע ביומן הפעילות).
- מנהלים יכולים להגביל כמה שינויים בדקה מותר לכל חיבור ("שינויים של AI בדקה — לכל אדם, אפליקציה או סוכן").

## יצירת טוקן API

טוקן מחבר את Make, ‏n8n או סקריפט לחשבון בשמכם, עם ההרשאות שלכם, מוגבל להיקף שבוחרים. אורחים וצופים לא יכולים ליצור טוקנים.

1. פותחים "הפרופיל שלי" ← "טוקני API" ולוחצים "טוקן חדש".
2. נותנים "שם", למשל "Make — לידים מהאתר".
3. ב"מה הטוקן יכול לעשות" מסמנים רק את מה שצריך, למשל קריאת בורדים ופריטים, יצירה ועריכה של פריטים, כתיבת עדכונים או Webhooks.
4. ב"לאילו בורדים" משאירים "כל הבורדים שלי" או מגבילים לבורדים מסוימים.
5. בוחרים "תוקף": מספר ימים, "שנה" או "ללא תפוגה".
6. יוצרים את הטוקן ולוחצים מיד "העתקה". הוא לא יוצג שוב, ומי שמחזיק אותו פועל בשמכם.

טיפים:

- טוקן עם "חשיפת סודות" קורא עמודות סודיות, ולכן יצירתו דורשת אימות דו-שלבי וקוד עדכני מאפליקציית האימות.
- ב"מגבלות שימוש" קובעים "בקשות לדקה" ו"בקשות ליום" לטוקן. ריק = ברירת המחדל של החשבון. מעליה – רק מנהל.
- כדי לעצור טוקן לוחצים "השבתה". חיבורים שמשתמשים בו יפסיקו לעבוד.

### טוקני שירות (למנהלים)

טוקן שירות שייך לשירות בעל שם ולא לאדם, ולכן הפעולות שלו נרשמות ביומן בשם "שירות: <שם>".

1. פותחים "ניהול החשבון" ← "חיבורים".
2. לוחצים "טוקן שירות חדש", בוחרים "תפקיד השירות בחשבון", הרשאות ובורדים.
3. מעתיקים את הטוקן.

שם אפשר גם לסמן "הצג את הטוקנים של כל החברים" כדי לראות ולהשבית טוקנים של כל אחד.

## חיבור Make או n8n

ל-Bines OS יש רכיבים מוכנים ל-n8n ואפליקציה ל-Make, עם טריגרים, פעולות וחיפושים על בורדים ופריטים. ההוראות מופיעות בקטע "n8n ו-Make" בתחתית "טוקני API".

ב-n8n:

1. פותחים Settings ← Community nodes ← Install.
2. מזינים את שם החבילה שמופיע ב-Bines OS ("שם החבילה") ומתקינים.
3. מוסיפים ל-workflow רכיב של Bines OS ויוצרים credential חדש.
4. מדביקים את "כתובת המערכת שלכם" (מופיעה ב-Bines OS) וטוקן API ושומרים. n8n בודק את החיבור.

ב-Make:

1. לוחצים "פתיחת קישור ההזמנה" ומתקינים את האפליקציה בארגון שלכם ב-Make. אם אין קישור, פונים למנהל המערכת.
2. בתרחיש מוסיפים מודול של Bines OS ולוחצים "Create a connection".
3. מדביקים את כתובת המערכת וטוקן API ושומרים. Make בודק את החיבור.

תנו לטוקן את ההרשאות שהזרימות צריכות, כמו קריאת בורדים, כתיבת פריטים ועדכונים, ו-Webhooks לטריגרים.

אפשר גם לקרוא ל-API מכל מודול HTTP: הכותרת Authorization: Bearer <הטוקן> וגוף JSON. "כל הנקודות של ה-API (תיעוד)" פותח את הרשימה המלאה.

## שליחת אירועים מהבורד לכלי אחר (Webhooks)

Webhook שולח אירוע מהבורד לכתובת חיצונית, למשל Custom webhook ב-Make או Webhook node ב-n8n. השליחה חתומה, ונשלחת שוב אם נכשלה.

1. פותחים את חלון האוטומציות של הבורד ועוברים ללשונית "Webhooks".
2. לוחצים "+ Webhook חדש".
3. מדביקים "כתובת" ובוחרים "אירוע", למשל "נוצר פריט", "סטטוס השתנה" או "ערך בעמודה מסוימת השתנה". חלק מהאירועים מבקשים לבחור עמודה, תווית או קבוצה.
4. לוחצים "אימות ושמירה". קודם נשלח challenge, והכתובת צריכה להחזיר אותו (ב-Make: מודול Webhook response, ב-n8n: ‏Respond to Webhook).

אחרי השמירה אפשר:

- ללחוץ "בדיקה" כדי לשלוח ניסיון.
- לפתוח "יומן" ולראות כל שליחה, וללחוץ "שליחה חוזרת" כדי לשלוח שוב.
- להציג את "סוד לחתימה" כדי לבדוק חתימות, או ליצור "סוד חדש".
- ללחוץ "כיבוי" או "הפעלה". Webhook שנכשל פעמים רבות נכבה לבד ("כובה אחרי כשלונות רבים").

מנהלים ימצאו קיצור דרך ב"ניהול החשבון" ← "חיבורים" ← "Webhooks".

### קבלת נתונים ושליחת פריטים מאוטומציות

- הטריגר "כשמתקבל webhook" ("Webhook נכנס") מפעיל אוטומציה כשכלי חיצוני קורא לו.
- הפעולה "שליחה לאינטגרציות (n8n / Make)" שולחת פריט לאינטגרציות שלכם בערוץ שבוחרים.

איך בונים אותן – ב[אוטומציות](automations.he.md).

## מעקב אחרי הזרימות ב-n8n, ‏Make ו-Zapier

מנהלים יכולים לחבר את החשבונות של n8n, ‏Make או Zapier ב"ניהול החשבון" ← "זרימות", ולראות מה פועל, מתי רץ לאחרונה ואיפה נכשל.

1. לוחצים "חיבור חדש" ובוחרים "כלי".
2. ממלאים כתובת או אזור, ומפתח. המפתח נשמר מוצפן ולא מוצג שוב.
3. לוחצים "בדיקת חיבור".

ב"הגדרות" בוחרים "מי רואה את הזרימות", אם לשלוח "התראה כשזרימה נכשלת", ואם ה-AI רשאי להכין או לערוך זרימות (כל זרימה של AI מחכה לאישור ונשמרת כבויה). בחלק מהכלים אפשר רק לצפות. את הזרימה עצמה עורכים בכלי ("פתיחה בכלי").
